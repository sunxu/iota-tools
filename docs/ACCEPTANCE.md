# Mac 实机验收清单

**必须在隔离节点上完成以下验证才可替换旧环境。**

- [ ] Finder 双击 IOTA Managed 后原始 IOTA App 不被修改，也不产生重复进程
- [ ] LaunchAgent 在 GUI 登录后只有一个 Supervisor，stop 状态重登仍有效
- [ ] 端口 8899、8877 仅绑定本地回环地址，冲突时不杀其他进程
- [ ] 本地测速 XML 和配置端口一致，实测上下行 HTTP 行为符合预期
- [ ] IOTA 内实际 Python、requests、OpenSSL 与其它 TLS 客户端都使用受控代理和 CA
- [ ] macOS 全局代理与系统钥匙串未被偷偷修改
- [ ] IOTA 自动更新时代理仍工作，更新器不会被意外杀死
- [ ] 更新器自行重启 IOTA 后，Supervisor 的安全接管恢复了原代理环境
- [ ] 退出/崩溃/重启限制正确，状态文件与清理无残留
- [ ] UploadPart 真实五并发，第六个请求等待；取消与断线正确释放名额
- [ ] 故障后新请求回退 7890；恢复探针不上传正文，业务 HTTP 5xx 不触发代理故障
- [ ] R2 GET 初始请求保持默认上游路线，非对象 GET、管理 API、多 Range 保持透传
- [ ] 500 KiB/s、10 秒滚动窗口触发准确；零字节窗口也能触发，正常高速请求不接管
- [ ] 替换代理使用原始 URL 与端到端请求头，不构造 Range，不泄漏签名 URL
- [ ] 已发送部分正文后，强 ETag、响应元数据及 SHA-256 前缀校验通过，后续正文无重复/遗漏
- [ ] 同时出现 9 个慢 GET 时最多 8 个接管，第 9 个不排队并继续原路线
- [ ] 替换代理失败、签名过期、ETag 不一致、前缀不一致时安全回退/失败
- [ ] 客户端取消后及时关闭上游连接并释放接管名额
- [ ] `tah-control status` 展示下载计数和最近事件；不记录 URL、认证头或正文
- [ ] 下载接管与 UploadPart 五并发独立，不互相占用额度
- [ ] 移除旧 Watchdog 后，上游异常行为经过验证

CI 只能证明单元与集成测试，不能替代以上实机测试。
